# 2026-05-30 IMU 与巡线调整记录

## 已完成修改

1. 增加 IMU 连通性测试模块

- 新增 `IDC/HARDWARE/IMU_TEST/imu_test.c` 和 `imu_test.h`。
- 使用 PB10/PB11 软件 I2C 读取 ICM20948。
- 读取 `WHO_AM_I = 0xEA`，并周期采样加速度、陀螺仪和俯仰角 `p10`。
- 在主循环中初始化 `ImuTest_Init()`，并周期调用 `ImuTest_Task(now_us)`。
- 串口调试输出增加 `IMU:id/on/ok/fail/ax/ay/az/p10`。
- 实车串口已看到 `id=0xEA on=1 ok` 持续增加、`fail=0`，说明 IMU 通信链路基本可用。

2. 调整巡线方向

- 当前巡线基础速度使用负 ERPM，让 USER 巡线启动后车辆按现在车头方向前进。
- 当前 CCD 看到线偏左时，转向量按遥控左转方向修正。
- 目前这轮修改的目标是解决“巡线时向后走”和“左右反”的问题。

3. 降低巡线动作过猛

- 巡线最大基础速度降到 `7000 erpm`。
- 最大转向量降到 `2500 erpm`。
- 丢线转向量降到 `1800 erpm`。
- 比例系数降为 `KP = 2`，微分项保持 `KD = 0`。

4. 提高 CCD 抗干扰能力

- CCD 阈值从简单中值改为 `min + contrast * 40 / 100`。
- 增加最小对比度过滤，低对比度时判定丢线。
- 增加黑线宽度上限过滤，宽度过大时判定丢线。
- 目的是减少阴影、黑色地面、棕色木板被误识别为黑线的概率。

## 当前状态

- 旧的 USER 键巡线状态机仍然保留：
  - 正向巡线 15 秒。
  - 原地转 180 度约 1.5 秒。
  - 反向巡线 1.5 秒。
  - 停止。
- IMU 目前只接入测试打印，没有接入夹爪逻辑，也还没有接入自动爬坡状态机。
- 夹爪仍按现有遥控通道逻辑控制。

## 待完成问题

1. 巡线实测复核

- 确认车辆现在是否按新车头方向前进。
- 确认 CCD 看到线偏左时，车辆是否实际向左修正。
- 若仍然左右反，只需要优先检查 `line_follow.c` 里 `steer_erpm` 的符号，不再同时改基础速度方向。

2. CCD 阈值继续调参

- 当前黑线阈值比例为 40%。
- 若仍然把阴影当线，可以尝试降到 35% 或 30%，同时观察 `LineFollow_Width`。
- 若经常丢线，可以适当放宽 `LINEFOLLOW_MAX_WIDTH_THRESHOLD` 或降低 `LINEFOLLOW_MIN_CONTRAST`。
- 更稳的方案是先识别白胶布区域，再在白胶布区域内找黑线。

3. IMU 自动爬坡状态机

- 目标流程：
  - 巡线上坡。
  - IMU 判断到达坡上或坡度变化后，右转 90 度。
  - 再上坡。
  - 左转 90 度。
  - 再上坡。
- 第一版可以先用定时原地转 90 度验证流程。
- 更稳版本应使用陀螺仪 Z 轴积分控制 90 度角。

4. 狭窄通道转向策略

- 仅靠两后轮差速时，严格以全车几何中心旋转并不容易，因为驱动轮连线通常不在车体中心。
- 空间很窄时可以先做差速微调，让一侧速度小、另一侧速度大，降低转弯半径。
- 若必须接近车体中心旋转，需要结合前后轮位置做运动补偿，或者增加机械/轮组自由度。

5. 工程验证

- 需要在 Keil 中重新编译确认。
- 当前命令行环境没有可直接调用的 Keil/ARMCC 编译命令，因此最终编译结果以本机 Keil 为准。
